# Public-execution feedback: prospective proposal-revision screen

Protocol and transport-free interface frozen before fresh responses. No paid
executor is qualified yet. This changes the proposal interface, not the closed

## Evidence and question

The public-only audit of all32 completed independent-joint responses found129
raw programs,107 consistent with the exact displayed examples,22 inconsistent.
Regeneration had no compatible raw program in3/8 cases (0,6,7); root A1/8 and
repeat1/8. No target outcomes were read by this audit. Feedback can address these
observed contradictions, but cannot disambiguate already-compatible programs
without new information or improved prior knowledge. Most proposals already fit.
Do not represent feedback as an established solution to conditional calibration.

Question: at equal revision-call and completion caps, does trusted interpreter
feedback improve fresh predictive quality over a revision call given the same
history and previous programs but no execution table?

## Frozen design

Eight fresh source programs, seeds35100000+i, i=0..7. Input seeds
36100000+100*i+j, j=0..34. First THREE examples are the entire public history;
last32 are fixed prediction targets. No unobserved query is made in this screen.
Keep every sampled program, ERROR, constant output, abstention and poor case.

Use exact Luna medium/standard OpenAI route,16384 completion cap, no temperature,
same typed source-valid response schema. Initial proposal call seed37100000+10*i
uses the unchanged public-history request. Then make one feedback revision and
one context-only revision, both seed37100000+10*i+1, alternating order by parity.
Both revision prompts contain the SAME original raw candidate pool and observed
history, never the other revision's response. Only feedback receives deterministic
example-index/actual-output/expected-output/pass rows. All candidates are shown,
not just failed ones. No adaptive retries, repair loop, or feedback from targets.

The feedback is a computational aid derived entirely from information already
available to the control. This is not a claim of identical actual token costs:
record prompt, output and reasoning tokens separately. Never include a hidden
program, target answer, source seed, or undisplayed example in either prompt.

Compile and locally expand all three raw response pools using the same original
history. Endpoint arms: initial alone; initial union feedback revision; initial
union context-only revision. Use unchanged syntax-prior restricted weights and
exact syntax deduplication; no global posterior interpretation or reweighting.
No compatible support means explicit abstention with loss1. Seal every case and
arm forecast before loading target outputs. No case replacement or early efficacy
peek. Interpretation distinguishes observed-fit, diversity and prediction.

## Metrics and fixed screen gate

Report raw and unique observed-fit counts, compatible-case coverage, expanded
support counts, all per-case target half-Brier/zero-mass/NLL, and paired differences.
The screen passes only if feedback endpoint support exists in all8 cases, its
mean Brier is at least10% lower than context-only revision (control mean must be
positive), target zero-mass count is nonworse, and it wins on at least3 cases by
more than0.01 Brier. Report every loss/tie; no supported-only denominator.

This eight-case screen is exploratory, not a powered significance claim or
non-myopic result. Passing permits only a separately frozen joint-simulator
validation. It does not bypass independent query-ranking, actual budget-matched
depth1/2/3, compute-matched myopic/random controls, or sealed paired endpoints.
Failure closes this exact feedback interface; no threshold/seed/cap rescue.
