# ClarifyBench Source Audit Result

## Decision

The released ClarifyBench harness fails the zero-call eligibility screen for a
native non-myopic BED result. Do not run a paid ClarifyBench policy or construct
a holdout from this snapshot.

ClarifyBench is a useful clarification and tool-use benchmark, but the release
does not provide a belief over alternative user worlds or a
question-conditioned answer tree. Each record supplies one gold trajectory,
and its later requests are enumerated from a fixed list before interaction.
The resulting ask-versus-act problem is principally myopic parameter
completion, not planning over path-dependent information states.

The number of fixed follow-ups ranges from zero to six. Their existence makes
the conversations sequential in an ordinary workflow sense, but it does not
make clarification actions non-myopic: the follow-ups are supplied
unconditionally rather than selected by prior questions or answers.

## Harness Evidence

The released `main.py` builds:

```python
all_requests = [("initial", user_query)] + [
    ("follow_up", req) for req in follow_ups
]
```

The main loop calls `get_response_to_question`, but does not call
`get_next_request` and does not advance `UserSimulator.current_turn`.
Meanwhile, the data loader assigns missing tool-call turns to turn one. All
2,304 raw calls lack native turn annotations. Consequently, the released
simulator does not expose a clean request-local, state-transition model for
non-myopic evaluation.

Clarification answers are generated by an LLM from the single gold tool-call
trajectory. The repository mentions EVPI only in result/reporting compatibility
fields, including a baseline literal of zero; it does not ship the paper's SAGE
or POMDP policy implementation. No top-level license file is present in the
inspected snapshot.

## Consequence

Adapting this release would require inventing alternative user worlds,
question-to-answer likelihoods, and an endogenous transition model. Those
choices would create a new synthetic environment and make the LLM less clearly
load-bearing than the current tau-Knowledge direction.

ClarifyBench is therefore closed as the next headline route. It remains
relevant related work for uncertainty-aware clarification, but no OpenRouter
call, repair, threshold tuning, or OatML job is authorized from this audit.
