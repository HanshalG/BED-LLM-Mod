This NEW descriptive analysis does not refit weights in the prior direction audit
or rescue a closed gate. The target bank has been examined by the analyst; although
target fields are excluded from fitting, this is NOT untouched confirmation.

Use the same bound July 32-tree bank, initial/first-branch supports and all saved
root queries. Only the eight separately seeded validation_supports draws per tree
fit its scalar interpolation weight. Verify validation seeds match 28500+8*i through
28507+8*i, and are distinct from that tree's saved target_seed. Validation and target
concepts can overlap naturally; do not select or remove them based on that overlap.

Weight each validation draw equally, each rule entry within draw equally, each root
equally. On fixed integers 0..100 including queried integer, compute exact A,B for
initial-filtered versus retained-refresh predictions as in the direction audit.
Fit a single t per tree by t=clip(-A/(2B),0,1), with t=0 if B=0. No prior search,
root-specific weights, alternative loss, tuning grid, exclusions or fallback trials.
One parameter is fitted from validation data; do not call it a Bayesian weight.

first_branches, validation_supports, then exclusively create WEIGHTS.json for all32.

loss to both exact parent initial-filtered and uniform-refresh losses on every root;
retain all trees. Report target gains, per-tree differences, fitted-weight distribution
and validation/target direction agreement. Zero model calls; no new endpoint,
scientific gate, paid permission or older-result rewrite.
