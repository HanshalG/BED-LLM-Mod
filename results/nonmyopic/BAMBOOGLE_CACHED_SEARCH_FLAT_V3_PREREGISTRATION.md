# Bamboogle Flat-Protocol v3 Contingent Preregistration

## Why One Final Interface Attempt Is Justified

The prior result closed a third attempt unless a substantially different,
prospectively justified interface became available. Both previous failures
were transport failures before scientific mechanics: prompt-only JSON had one
extra brace in five calls, while strict JSON Schema had no routable GPT-5.4
provider. Since then, the same non-reasoning GPT-5.4 endpoint completed 38/38
strict flat-line HoVer responses with no retry, repair, reasoning token, or
forced exit. That is new serving evidence for a materially different wire
protocol.

This document therefore supersedes only the old no-third-serving restriction.
It does not reinterpret either failure or change any Bamboogle task, retrieval
action, policy, endpoint, scientific gate, or split. Version 3 is the final
Bamboogle serving attempt. Any serving failure closes Bamboogle permanently
for this project.

## Phase A: Flat Serving

- Same five released mechanics tasks and non-reasoning `openai/gpt-5.4`.
- Same eight hypotheses, integer weights summing to 100, four root queries,
  and four precommitted second queries.
- Exactly five fresh physical calls, temperature `0.0`, 512-token maximum.
- Ordered line grammar:
  `H01|weight|hypothesis` through `H08`,
  `R01|query` through `R04`, and
  `F01|query` through `F04`.
- Strict parser accepts exactly 16 ordered nonempty lines, with no extra text,
  JSON, repair, extraction, or reissue.
- Existing support uniqueness, weight, query length, and global query
  diversity checks remain unchanged.
- Zero Wikipedia requests and no scientific endpoint access.
- Zero model retries, reasoning tokens, or forced exits.
- Cost cap: `$0.15`.

All gates must pass. Phase A responses are discarded rather than reused.

## Phase B: Contingent Mechanics

Only a full Phase A pass authorizes a fresh mechanics run. The scientific
protocol and all gates are exactly those frozen in
`BAMBOOGLE_CACHED_SEARCH_MECHANICS_PREREGISTRATION.md`: five tasks, 65 model
calls, 60 cached Wikipedia retrieval actions, four roots per task, adaptive
and precommitted second queries, entropy-selected myopic/adaptive/fixed
policies, and gold answer mass loaded only after the raw checkpoint.

The sole change is response serialization:

- initial: eight `H` lines, four `R` lines, four `F` lines;
- root refresh: eight `H` lines and one `A01|query` line;
- terminal: eight `H` lines.

No scientific prompt input, support count, policy, endpoint, threshold, retry,
or repair changes. The full cost cap remains `$0.75`; projected spend is below
`$0.40`. Failure closes this Bamboogle route. A full pass authorizes only a
separately frozen opportunity-20 protocol; development and holdout remain
sealed. OpenRouter is the only compute provider and OatML is prohibited.
