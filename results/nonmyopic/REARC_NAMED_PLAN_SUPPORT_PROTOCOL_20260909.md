## Matched generation

Each arm uses three calls: plan, compile, public-feedback repair. Contrasting
asks for four explanations differing in a prediction-relevant assumption;
ordinary asks for four notes of the model's unconstrained best solution plan.
Both plan responses have the same four fixed fields p0,p1,p2,p3 and 512-character
description limits. API and local checks use the identical JSON Schema; field
order is irrelevant. Total serialized request bytes retain their separate cap. These are jointly generated descriptions, not independent statistical
samples. Labels are not proof of semantic diversity.

Compilation sees the same full DSL, public inputs and one observed output.
Contrasting requests two implementations per explanation, ordinary eight
hypotheses using its plan. Both get exactly one repair on the observed example.
Retain16program attempt slots, including malformed batches and duplicates. No
extra request, invalid-batch salvage, or refill. An invalid plan terminates the
block; invalid compilation still permits the one scheduled repair. Report whether
the intended mechanism mapping was followed; do not infer that from labels.

No symbolic expansion in either primary arm: it gave no measured benefit in the
previous study and consumed substantial local runtime. This is NOT a result
against classical synthesis. Any later efficacy study requires a stronger usable
classical comparator in addition to equal-compute myopic and random policies.

Condition convertible unique programs on the single visible output using the
existing uniform finite-pool prior and deterministic likelihood. Duplicate family
names or programs do not multiply prior mass. Keep failed future predictions in
the forecast. Empty consistent support gives unit failure forecast. Record
program count, distinct predicted-output signatures, non-failure output diversity,
query entropy and failure probability separately.

## Frozen exploratory gates

After both arms on all six tasks, require contrasting demo0 coverage >=4/6 before
opening query or target outputs. Otherwise initial-coverage null.
Seal all ten predictions per task/arm before any hidden output. Then require:

- Positive mass on the actual query answer in at least8/12query cases.
- At least3/6tasks have a designated query with >=2different positive-mass,
  non-failure predicted outputs before labels; synonyms/failed outputs do not count.
- Contrasting mean whole-grid Brier over all ten outputs improves by >=.01 over
  ordinary, with >=2/6task-level gains >=.01, and is nonworse in fixed-canvas Brier.

All three must pass. Report all tasks and both query/target strata regardless of
direction. Six tasks are an exploratory gate, not powered efficacy evidence or
a guarantee of monotonic depth. A pass opens only a separately frozen sequential
opportunity/refresh-transition fidelity study. No depth or headline authority.
These new pre-response criteria do not reinterpret or override the old failed gate.

## Schema correction boundary

This successor corrects the character/byte and array-ID schema mismatch only.
The scientific gates and all call, token, candidate and price caps stay unchanged.
It neither rescues nor replays the old response as new evidence. The old
mechanism cohort stays closed. The new ordinary and contrasting prompts both
ask for complete concise statements well within the same512character limit.

Local structural acceptance uses Draft202012Validator on the exact API schema,
not handwritten length/ID checks. Plan fields may appear in any JSON order;
canonicalization preserves their text. Whitespace-only descriptions remain
schema-valid and are flagged as semantic diagnostics, not misreported as schema
violations. No semantic correctness is inferred from schema acceptance. DSL
compilation is a separate executable-validity check with its existing limits.
Pin requirements-plan-contract.txt and runtime dependency versions before calls.
Require Unicode-boundary/schema parity and full named-plan update tests first.
