# Execution-feedback path toward non-myopic BED

## What the new evidence establishes

The saved initial Luna response was replayed in a separate diagnostic container
on only the already-paid first input. No generator, unqueried output, target file,
or model request was available to the worker. All four failures are TypeErrors:
graphs 1-3 reach fgpartition with a row; graph 4 reaches compress with a row.
The grid was 26x26; first(I) produces a tuple of 26 integers. Thus the earlier
row/grid explanation is now directly observed, not merely inferred. The three
longer proposals also share their entire failing prefix, indicating little useful
diversity in that call. This does not prove a model-wide inability to reason.

The frozen qualification remains failed and closed. The diagnostic is not a
rescored endpoint, a successful repair, or permission to rerun that panel.

## Distinct architecture to qualify next

Use an execution-guided program proposer, not one-shot graph emission. Keep the
safe generic DSL and numerical posterior/scoring code. Make the public contract
explicit: each program maps ONE input_grid to ONE output_grid, independently for
each example; input_grid never denotes a list of demonstrations. Supply a small
task-independent working grid-to-grid graph and explicit Grid/Row/Object/Callable
semantics. The generic example must not encode a selected task transformation.

Bound the proposal-update operation prospectively: one initial batch of four
graphs and at most one repair batch of four, with the same fixed call/token caps
in every branch and online update. Feedback contains only schema errors, failing
step/operator, argument/result types, and discrepancies on actually queried
examples. No source verifier, hidden target, oracle-selected edit, or unqueried
answer enters feedback. A malformed graph gets diagnostic feedback, not silent
partial salvage; retain raw programs, work counts, invalid mass and repair costs.
Do not auto-correct graphs in numerical code or silently select a best program.

Static type checks cannot simply ban first(I): taking a row can be a valid
intermediate. Higher-order and polymorphic DSL operations require either sound
type propagation or runtime checks, not a whitelist designed around these four
failures. Preserve expressivity and use explicit execution failure as an outcome.

## The scientific bottleneck after execution

Successful repairs are not yet Bayesian calibration or a depth result. A finite
pool fitted to three examples can be confidently wrong everywhere else. Require
predictive transfer on untouched tasks against equal-call answer-blind proposal
plus repair, an execution-guided myopic control, and symbolic search. Same public
inputs and observed outputs for scoring, unique-program prior, failure mass, and
sealed fixed-target Brier endpoints. All proposals and repair work count toward
the controls' compute allowance. Four one-shot graphs are not a sufficient
compute-matched comparator for an eight-graph execution-guided pipeline.

Then test the actual mechanism: does a query change the next generated support in
a predictably useful way? A planner branch must invoke exactly the same bounded
proposer/repair/update operation as an online step, using only that branch's public
history. Simulated worlds remain separate from policy belief state; never inject
the sampled truth into the policy support. Keep each simulated program persistent
across all answers along its trajectory. Undefined transformations give explicit
failure outcomes, not branch deletion or prior reset.

Before any depth sweep, bank a branch-transition fidelity test: compare predicted
query rankings with independent online update draws on the same public histories,
using a fixed target risk and matched-call myopic and random-query controls. Freeze
the number of draws, ranks, effect threshold and uncertainty rule before responses.
An answer-blind pool expansion that performs equally well is evidence for more
search, not non-myopia over generative belief dynamics.

## Horizon and environment decision

RE-ARC is only a candidate environment. Querying a new grid means revealing its
output, not intervening arbitrarily on a reference generator. Public input-pool
selection must be fixed and accounted for. Candidate programs may be undefined on
that pool; their failure probability cannot disappear from the predictive model.
Do not assume source-generator validity implies coherent cross-program worlds.

Use the same fixed-target proper loss for h1/h2/h3 and terminal assessment.
Demonstrate that useful distinguishing queries and adaptive continuations exist
before paying for nested planning. Compare depth to equal-call width/repair,
random acquisition, fixed-support lookahead and real-history-only regeneration.
Nested conservative policy improvement can protect predicted Bayes risk under a
coherent model; it cannot guarantee monotonic held-out performance under an
incorrect LLM-induced distribution. Report paired uncertainty, not forced ordering.

If accurate programs make one-step acquisition saturate, stop this environment
for the headline instead of increasing difficulty after inspecting test outcomes.
If feedback fixes execution but not predictive coverage, address coverage before
depth. If coverage passes but branch fidelity fails, do not substitute an oracle
updater and call the resulting depth effect LLM-native.

## Next executable decision

Design one fresh, metadata-selected development cohort disjoint from the closed
four tasks. Freeze generator attempts, public input/label split, repair prompts,
caps, transfer gates and controls before any new responses. No calls are authorized
by this memo: the fresh cohort source contract and complete execution-feedback
runner still need qualification. The existing failed panel can be used only as
explicitly retrospective engineering evidence, never as a fresh evaluation.

This is a route to testing the full goal, not a declaration that a typed interface
or a clean runtime constitutes the desired positive non-myopic result.
