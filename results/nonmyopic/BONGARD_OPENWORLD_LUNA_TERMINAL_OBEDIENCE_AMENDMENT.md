# Bongard-OpenWorld Terminal Label-Obedience Amendment

Date frozen: 2026-08-07, before any Bongard serving, mechanics, development,
or confirmation model response.

## Validity Gap

The existing branch gate requires each simulated one-answer belief to predict
its supplied positive or negative label better than a constant-half baseline.
The independently regenerated terminal beliefs receive two real query labels,
but the protocol previously checked only that those labels appeared in the
prompt and parsed history. It did not require the resulting predictive belief
to retain them.

A terminal generator that ignores the newly observed labels is not a valid
sequential belief updater. A held-out endpoint difference from such beliefs
cannot support the intended LLM-native path-dependent-belief claim, even if it
is numerically favorable.

## Frozen Gate

For every distinct terminal history already generated by mechanics,
development, and confirmation:

1. verify that all four initial labels are preserved exactly;
2. identify the exactly two additional queried labels;
3. compute the terminal mixture's Brier score on each queried image; and
4. pool those scores separately for positive and negative queried labels.

Both classes must occur, and each class-conditional mean Brier must be
strictly below `0.25`, the constant-half predictor. Failure makes the block a
mechanics failure before any scientific endpoint can authorize a claim.

The metric is persisted and independently replayed from raw terminal
responses. It uses only labels that the policy had already observed. Endpoint
labels remain sealed under the existing boundary.

## Scope

This is a pre-response validity gate. It adds no request, prompt, response,
seed, batch, token, cost, task, policy, endpoint, or scientific threshold. It
cannot turn a null result into a positive result; it can only stop a run whose
terminal LLM belief fails to incorporate its observed data.
